# 验收标准编写指南

## 基本结构

```markdown
## 6. 验收标准

| ID | 功能点 | 验收条件 | 优先级 |
|----|--------|----------|--------|
| AC1 | 用户注册 | 输入有效邮箱和密码，返回成功 | P0 |
| AC2 | 用户注册 | 输入已存在邮箱，返回"邮箱已注册" | P0 |
| AC3 | 用户登录 | 输入正确凭证，返回Token | P0 |
| AC4 | 用户登录 | 输入错误密码，返回"密码错误" | P0 |
```

## 验收条件格式

### 格式模板

```
[输入/前提条件] -> [操作] -> [预期结果]
```

### 示例

| 格式 | 示例 |
|------|------|
| 输入->操作->结果 | 输入有效邮箱 -> 点击注册 -> 显示注册成功 |
| 前提->操作->结果 | 已登录用户 -> 访问个人中心 -> 显示用户信息 |
| 异常->操作->结果 | 网络断开 -> 提交表单 -> 显示网络错误 |

## 优先级定义

| 优先级 | 标记 | 说明 | 是否阻塞上线 |
|--------|------|------|--------------|
| 关键 | P0 | 核心功能，必须通过 | 阻塞 |
| 重要 | P1 | 重要功能，建议通过 | 不阻塞 |
| 一般 | P2 | 辅助功能，可后续迭代 | 不阻塞 |

## 验收条件类型

### 功能性验收

| 类型 | 说明 | 示例 |
|------|------|------|
| 正常流程 | 正常使用时应该正常工作 | 登录成功返回Token |
| 异常流程 | 异常情况下应该正确处理 | 输入错误密码提示错误 |
| 边界条件 | 边界值应该正确处理 | 空字符串、超长输入 |
| 权限验证 | 权限检查应该正确 | 未登录无法访问 |

### 非功能性验收

| 类型 | 说明 | 示例 |
|------|------|------|
| 性能 | 响应时间符合要求 | 登录响应<200ms |
| 安全 | 安全性检查 | 密码加密存储 |
| 兼容性 | 多环境兼容 | 各浏览器正常 |
| 可用性 | 用户体验 | 提示信息清晰 |

## 编写原则

### 1. 明确具体

❌ 错误：注册功能应该能正常工作
✅ 正确：输入有效邮箱和密码，点击注册，返回200，数据库新增一条记录

### 2. 可测试

❌ 错误：系统应该反应迅速
✅ 正确：API响应时间<200ms

❌ 错误：界面应该美观
✅ 正确：所有按钮居中显示，间距统一

### 3. 覆盖全面

| 类别 | 覆盖率 |
|------|--------|
| 正常场景 | 100% |
| 异常场景 | 主要异常必须覆盖 |
| 边界条件 | 最大/最小值、空值 |
| 权限场景 | 有权限/无权限 |

### 4. 独立描述

每条验收标准应该独立，不依赖其他AC的执行结果。

❌ 错误：AC2依赖于AC1执行后的状态
✅ 正确：AC2可以独立执行和验证

## 常见验收标准模式

### CRUD 操作

| 操作 | AC模式 |
|------|--------|
| Create | 输入有效数据 -> 创建 -> 成功返回，数据存在 |
| Create | 输入无效数据 -> 创建 -> 返回错误提示 |
| Read | 存在的数据 -> 查询 -> 返回正确数据 |
| Read | 不存在的数据 -> 查询 -> 返回空或404 |
| Update | 更新存在数据 -> 成功 -> 数据已更新 |
| Update | 更新不存在数据 -> 返回错误 |
| Delete | 删除存在数据 -> 成功 -> 数据已删除 |
| Delete | 重复删除 -> 返回错误 |

### 验证类

| 场景 | AC模式 |
|------|--------|
| 必填字段 | 不填必填字段 -> 提交 -> 提示必填 |
| 格式校验 | 输入格式错误 -> 提交 -> 提示格式错误 |
| 长度限制 | 输入超长 -> 截断或提示超长 |
| 唯一性 | 输入已存在值 -> 提交 -> 提示已存在 |

### 权限类

| 场景 | AC模式 |
|------|--------|
| 未登录 | 未登录 -> 访问受保护接口 -> 返回401 |
| 无权限 | 普通用户 -> 访问管理员功能 -> 返回403 |
| 越权 | 用户A -> 修改用户B的数据 -> 返回403 |

### 性能类

| 场景 | AC模式 |
|------|--------|
| 响应时间 | 正常请求 -> 响应 -> <200ms |
| 并发 | 10个并发请求 -> 全部成功响应 |
| 大数据 | 查询10000条数据 -> 正常返回或分页 |

## 验收标准模板

### API 接口验收

```markdown
| AC1 | [API名称]正常调用 | 传入有效参数 -> 调用API -> 返回200，data正确 | P0 |
| AC2 | [API名称]参数校验 | 传入无效参数 -> 调用API -> 返回400，提示错误信息 | P0 |
| AC3 | [API名称]未授权 | 不带Token调用 -> 返回401 | P0 |
| AC4 | [API名称]无权限 | 普通用户调用 -> 返回403 | P1 |
| AC5 | [API名称]不存在资源 | 查询不存在ID -> 返回404 | P1 |
```

### 页面/功能验收

```markdown
| AC1 | 页面加载 | 访问页面 -> 页面正常渲染，无报错 | P0 |
| AC2 | 数据显示 | 数据加载完成 -> 显示正确数据 | P0 |
| AC3 | 用户交互 | 点击按钮 -> 触发正确行为 | P0 |
| AC4 | 错误提示 | 操作失败 -> 显示明确错误提示 | P1 |
| AC5 | 加载状态 | 数据加载中 -> 显示加载动画 | P1 |
```

## 验收标准与测试用例

一条验收标准可以对应多条测试用例：

```
AC1: 登录成功
  TC1.1: 用户名正确，密码正确 -> 登录成功
  TC1.2: 邮箱正确，密码正确 -> 登录成功
  TC1.3: 手机号正确，密码正确 -> 登录成功

AC2: 登录失败
  TC2.1: 用户名错误 -> 登录失败
  TC2.2: 密码错误 -> 登录失败
  TC2.3: 用户名密码都错误 -> 登录失败
```

## 验收标准检查清单

编写完成后，检查以下问题：

- [ ] 每条AC都是可测试的
- [ ] 覆盖了所有P0功能
- [ ] 包含了主要异常场景
- [ ] 包含了边界条件
- [ ] 包含了权限验证
- [ ] AC描述清晰，无歧义
- [ ] AC之间相互独立
