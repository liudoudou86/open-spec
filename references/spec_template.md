# Spec 模板

## 模板结构

```markdown
# Spec: [功能名称]

## 1. 概述
- 功能简述
- 目标用户
- 业务价值

## 2. 功能列表

### 2.1 [子功能1]
- 描述：
- 优先级：P0/P1/P2
- 详细说明：

### 2.2 [子功能2]
- 描述：
- 优先级：P0/P1/P2
- 详细说明：

## 3. API规格

### 3.1 [API名称]
| 字段 | 值 |
|------|-----|
| Endpoint | /api/v1/xxx |
| Method | GET/POST/PUT/DELETE |
| Auth | 是否需要认证 |

#### Request
```json
{
  "field1": "类型 - 说明",
  "field2": "类型 - 说明"
}
```

#### Response - 成功
```json
{
  "code": 200,
  "data": {
    "field1": "类型 - 说明"
  }
}
```

#### Response - 错误
```json
{
  "code": 400,
  "message": "错误描述"
}
```

### 3.2 [API名称2]
（同上格式）

## 4. 数据模型

### 4.1 [Model名称]
| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | UUID | 是 | 主键 |
| name | String | 是 | 名称 |
| status | Enum | 是 | 状态: active/inactive |

### 4.2 [Model名称2]
（同名格式）

## 5. 业务流程

### 5.1 核心流程
```
[用户] -> [操作1] -> [系统] -> [操作2] -> [结果]
```

### 5.2 异常流程
```
[用户] -> [操作1] -> [系统] -> [错误提示] -> [用户修正] -> [重试]
```

## 6. 验收标准

| ID | 功能点 | 验收条件 | 优先级 |
|----|--------|----------|--------|
| AC1 | 注册 | 输入有效邮箱和密码，返回成功 | P0 |
| AC2 | 注册 | 输入已存在邮箱，返回"邮箱已注册" | P0 |
| AC3 | 登录 | 输入正确凭证，返回Token | P0 |

## 7. 边界条件

- 字段为空/超长
- 并发请求
- 网络异常
- 重复提交

## 8. 潜在风险 [可选]

对于简单功能可跳过。涉及多系统交互、敏感数据或复杂状态转换时推荐填写。

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 风险1 | 高 | 措施描述 |
| 风险2 | 中 | 措施描述 |

## 9. 监控与日志 [可选]

对于简单功能可跳过。涉及资金、安全或关键业务链路时推荐填写。

- 关键操作日志
- 错误监控
- 性能指标
```

## 填写指南

### 功能列表
- 每个子功能用P0/P1/P2标记优先级
- P0: 必须实现，阻塞上线
- P1: 重要功能，建议实现
- P2: 锦上添花，可后续迭代

### API规格
- 参考 `api_spec_guide.md` 编写
- 每个API都要考虑成功和错误两种Response

### 数据模型
- 参考 `data_model_guide.md` 编写
- 明确字段类型、必填性、默认值

### 验收标准
- 参考 `acceptance_criteria.md` 编写
- 每条验收标准应该可测试、可验证
- 格式：输入X -> 操作Y -> 预期结果Z
