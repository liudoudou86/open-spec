# Proposal: 用户登录注册系统

## 背景

当前产品没有用户系统，用户无法个性化体验和保存数据。
竞品都有完善的用户体系，我们需要快速补齐这块能力。

## 目标

- 实现邮箱密码注册和登录功能
- 支持JWT Token认证
- 用户可修改个人资料（昵称、头像）

## 范围

### In Scope（本期实现）

- 邮箱密码注册
- 邮箱密码登录
- JWT Token认证
- 修改昵称
- 修改头像

### Out of Scope（本期不实现）

- 手机号登录/注册
- 第三方登录（微信、Google）
- 密码找回
- 用户权限体系

## 初步想法

### 功能描述

1. **注册流程**
   - 用户输入邮箱、密码、确认密码
   - 系统校验邮箱格式、密码强度
   - 校验通过后创建用户，发送欢迎邮件（可选）

2. **登录流程**
   - 用户输入邮箱、密码
   - 系统校验凭证，返回JWT Token
   - Token有效期7天

3. **个人资料修改**
   - 用户可修改昵称（最多20字符）
   - 用户可上传头像（支持jpg、png，最大2MB）

### 用户交互流程

```
注册:
  1. 打开注册页面
  2. 输入邮箱、密码、确认密码
  3. 点击注册按钮
  4. 系统创建账户，返回登录态
  5. 跳转至首页

登录:
  1. 打开登录页面
  2. 输入邮箱、密码
  3. 点击登录按钮
  4. 系统验证，返回Token
  5. 跳转至首页，显示用户信息
```

## 风险与约束

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 密码安全 | 高 | 使用bcrypt加密，不存储明文 |
| Token安全 | 高 | 设置过期时间，支持Token刷新 |
| 头像存储 | 中 | 使用云存储服务 |

## 待确认问题

- [ ] 是否需要发送欢迎邮件？（影响API设计）
- [ ] Token有效期7天是否满足需求？（可能需要更长）
- [ ] 头像存储使用本地还是云存储？（影响技术方案）
- [ ] 是否需要记录用户最后登录时间？（影响数据模型）
